# 场景与动作

## 集成外壳

种子需要 React/TypeScript、`three` 与 `@types/three`。沿用宿主锁文件和构建工具，不为一个组件替换整个项目。`app/office-demo.tsx` 显示“演示，未连接真实任务执行器”，使用本地生活模拟；不能当无人值守或真实任务验证。

将 `Office3D` 的 roles、roleState、selected、onSelect、lifePlans 和 metrics 接到真实状态后，再移除演示说明。`app/office-styles.css` 从宿主允许的全局样式入口导入；样式限定在 `.ai-office-demo` 内，实际组件也需这个外层类，或按宿主的命名空间调整，避免覆盖其他页面。

外壳的生活作息默认采用 UTC+8。换时区时同步调整 routine/leisure 的时间计算、界面文案与边界测试，不能只修改后台调度时区。

样式默认从 Google Fonts 请求字体；离线或受限网络使用后备字体。要求完全离线时，移除远程导入，或在确认许可后由宿主本地托管字体。

## 动作要点

- 场景路线负责行走；剥离素材根节点水平位移，避免双重移动。
- AnimationMixer 和手动骨骼不能抢写。当前模式只在走路时更新相应 mixer，静态活动从 rest pose 设置；暂停的动画轨道也可能覆盖手动姿态。
- 阅读有书、手部目标和翻页；羽球有挥拍与球轨迹；工作有手部动作。游泳、睡眠、淋浴各自匹配姿态与地点。文字标签不等于动作。
- 每人独立座位。人物、椅子、手持物统一局部坐标；近景检查脚底、朝向、坐高和手部，不叠坐。
- 名字、卡片和模型共用选择逻辑：正确楼层 → 平滑定位 → 跟随移动。手动拖动保留观察自由；房间选择、复位和退出跟随应结束跟随。
- `renderer.setSize(w,h,false)` 避免样式反馈，ResizeObserver 用 RAF 合并。清理监听器、resize/animation RAF、renderer 和资源。
- 默认有动作；减少动作开关真正减少动作。预览明确标记、有自动恢复，不改写真实任务或长期遮住其状态。

## 新增第 N 人

外壳默认六人固定布局，不能只加名字。逐项检查角色与工具枚举、外观/性别映射、工位、全部活动座位和目的地、住宅、道路与门、跨楼层路线、镜头范围、生活偏好、人数文案、状态汇总、卡片和移动端。

同时安排 N 人到每种活动，检查坐标有限、座位间距和路线。第七人优先把角色、外观、工位和住宅改为按 role ID 关联，避免索引数组错配。

## 素材许可

包内只有程序化几何与项目姿态代码，没有 FBX 或纹理。`useLicensedModels=false` 关闭原模型加载；不要擅自复制第三方文件来消除缺失素材错误。

要照片级人物时，从官方来源核实目标实时渲染、托管与分发许可。原 WB 曾私有使用 Renderpeople 示例，并不意味着允许将文件塞进可分发 Skill 或新公开网站；私有也不是所有许可问题的通行证。没有合适许可时使用程序化人物，并说明外观限制。

## 楼层、首页与监督视角

当前模板：二楼为六人工位、会议及录制区域；一楼为电影院、游戏、泳池、羽毛球、健身及宠物，住宅和商城保持室外地面。首页先显示3D办公室，默认与复位镜头均选二楼；不是只改按钮名称。新公司可更改此约定。

楼层变更要同时更新几何父组、工位初始位置与工作目的地、所有活动座位、泳池/羽球绝对高度、房间定位、快捷按钮、楼梯及连接桥路由、跟随摄像机和默认楼层。`floor-layout.mjs` 提供共享坐标；`interiorPosition` 只映射旧室内位置，不能套到室外住宅或商城，也不能二次映射已更新坐标。六人使用独立位置。

`amenities-scene.ts` 是原创建模；`office-amenities.mjs` 提供六个健身位置及有界宠物动作。跑步和力量动作由 `human-motion.ts` 驱动，哑铃由 `life-scene.ts` 提供；健身加入 `leisure.mjs` 候选，而非强制循环。猫狗会行走、摆尾及休息，减少动作开关要减少动作；宠物不占业务角色或任务额度。保留明确的动作预览标签，真实任务优先。

维护场景后分别目视二楼默认工位、一楼娱乐、宠物与健身入口；坐标单元测试不等于姿态已目视核对。
