# 云端运行与提醒

## 无人值守

即时请求、长任务取回和定时工作分开。云端工作要有真正调度及授权连接。本地脚本、页面 setInterval、人物作息和模型口头承诺都不是后台服务。

先检查已有日程，避免重复创建。明确时区、触发点、执行器、工作目标、操作限额、错误通知渠道和检查记录。通过当前产品正式工具或 UI 管理，不手写伪造自动化指令。

在页面关闭/本机离线后跨过已授权触发点，核查云端 run ID、持久状态、实际回执和后续周期。手动 Run now 与真正定时触发分开验证；未来尚未触发就写“已配置，尚未验证”。

## 邮件与外部动作

- 新公司重新核实身份、授权、历史客户、排除名单、模板、配额与操作范围，不沿用 WB 的数量、价格或邮箱。
- 发送前原子预留额度，成功保存完整 claim、message/thread ID 和时间；结果不确定先查 Sent，不能直接重发。
- 人工回复、拒绝、退订、退信按规则停止追发。包含历史会话，不能只看新发送邮件。
- 已发出不等于已送达；退信独立统计，不抹去发送尝试。今日/累计、历史/新批次、首次/跟进分开，明确分母和检查时间。
- 人工回复进入持久高优先级提醒，在办公室场景之后、命令框和历史之前，显示来源消息、时间、负责人、下一步。站内提醒不等于手机推送、邮件通知或用户已读。
- 有已授权通知渠道时按要求通知；没有就说明缺口，不擅自连接。旧消息巡检不重复提醒，新消息更新并重新打开。

## 故障定位

| 症状 | 先查 |
|---|---|
| 今天没研究/没发信 | 当前本地日期的真实记录、平台日程是否启用、实际触发、执行器错误、OAuth、额度和窗口 |
| enabled 但没工作 | 平台日程与数据库快照是否不一致，各自核对时间 |
| Gmail 需重新授权 | 正式连接流程刷新，实际读取 profile 成功后确认；不编造关应用就断连 |
| 指令一直等整点 | 是否只入队、是否真正派发、取结果是否依赖页面 |
| 有回复没通知 | 历史会话覆盖、状态写入是否生成 alert、是否挤在长历史下面、统计是否只计新邮件 |
| 人物不动/姿态复位 | 开关、RAF、mixer 与手动骨骼冲突、目的地是否存在 |
| 加人崩溃 | 工位/座位/房屋/配饰越界与允许角色枚举 |
| 页面越来越长 | 卡片是否显示完整代码；短摘要加折叠，不删结果 |

观察到日程暂停不等于已知道为何暂停。授权过期与暂停可以同时存在，但不能虚构因果。恢复连接后还需核实任务与补跑的实际结果。

## 发布验收

按变更风险运行行为测试、类型检查和构建。按当前托管平台规则同步精确源码、打包产物并发布；构建后再取短期凭据，避免凭据在构建期间失效。秘密只走安全通道。

保留原站访问范围和真实记录。依赖私有网关的接口不能直接复制到公开站。非终态部署检查到终态；URL 和保存版本都不能证明发布成功。源码提交、构建、发布、浏览器验证和无人值守验证分别报告。

## 全邮箱赞助巡检（用户已授权时）

不能只查已追踪公司、系统发出的邮件或未读邮件。分页列出增量窗内全部入站候选，包含人工发起、未追踪、已读及归档会话，再读取相关会话上下文；关键词仅辅助，不是关系证据。默认排除垃圾箱和垃圾邮件，除非用户另有要求。区分人工回复、自动回执、会议纪要和无关广告；不明确的列待确认。

按 Gmail messageId 去重、threadId 管理会话；重复旧信不重开已处理提醒，新回复更新/重开同会话待办。先成功保存 alert，再写去重收据。手动历史会话可关联 lead，但不能伪造历史 outreach。示例回查7天、之后48小时重叠；范围应适配用户授权和邮箱量。所有分页及候选上下文处理完才推进成功游标，错误保存续查位置并提醒，不把部分扫描记为全部完成。

沿用既有云端日程，更新实际任务提示或确认其会读取共享规则，不能只保存一个不被执行器读取的 setting 就宣称生效。新旧触发点覆盖全天时避免重复建任务。此授权只涵盖检查和已授权渠道的提醒，不能顺带自动回信、发会议邀请、标已读或删除。站内提醒与手机主动推送分别验收。

## 手机访问与更新

同一部署地址可在手机浏览器打开；iPhone 可用 Safari 分享菜单加入主屏幕，使用相同获授权账户。发布成功后手机可能仍持有旧页面：先关闭重开或刷新，再用 Safari 直接打开同一地址核对明确的新版界面标志。不能保证每台设备即时清除缓存，也不能把桌面验证说成手机已验收；不要求先重装，不承诺已实现PWA或手机推送。
