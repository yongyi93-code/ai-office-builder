# 状态与执行架构

| 层 | 负责 | 不能证明什么 |
|---|---|---|
| 3D表现 | 位置、路线、动作、镜头 | 不能证明研究、发信、部署发生 |
| 工作台 | 指令、状态、结果、提醒、审计 | 保存指令不等于执行成功 |
| 执行器与调度 | 调用实际工具，保存服务商证据 | 日程启用不等于每次成功 |

角色注册集中维护稳定 ID、职责、颜色、外观映射和可用能力；前后端与工具 schema 使用一致的允许角色。程序员不自动获得终端、文件和生产发布权限；经理也不自动扩大团队权限。

## 最小持久记录

- `command`：ID、requestId、原始 text/target、status、createdAt、claimId/claimedBy、startedAt、finishedAt、result、sources、provider response ID。
- `run`：taskId、role、source（manual/scheduled）、state、step、summary、startedAt、heartbeatAt、finishedAt、结果证据；只记录真正业务运行。
- `lead/outreach`：业务证据、发送尝试、服务商 message/thread ID、回复、退信、停止状态。
- `alert`：稳定 ID、category/priority、源消息与会话 ID、receivedAt、更新时间、下一步、resolved。同一会话新消息更新并重新打开，重复读旧消息不重新打开。
- `setting`：连接和日程最近实际核对、角色政策、经理指导。enabled 不是健康检查。
- `life`：每个角色的模拟精力、偏好、近期活动、当前选择、开始和结束时间；不是业务成果。
- 关键更新保留审计版本；分页不能漏掉历史客户、未处理提醒和正在执行的任务。

## 队列不变量

1. requestId 幂等创建，同 ID 不能更换文本或岗位。
2. 数据库条件更新原子领取，只有 queued 可转 running，只有一位消费者获得 claimId。
3. 原始任务与领取身份不能被结果载荷覆盖。合法终态不可自动重开；取消后不执行。
4. 派发后保存 provider response ID，按真实状态轮询。dispatching 后无 ID 属于不确定，不能重复提交计费请求。
5. 超时写 stale/blocked，先核对服务商记录，不直接重发。完成必须有结果或可核实产物，不能以已排队代替。
6. 浏览器轮询只改善交互。云端消费者还需取回无人值守结果；缺少该路径就直说。

## 同步和自主生活

手动与自动运行共用生命周期，详见 [execution-contract.md](execution-contract.md)。真实 running 优先于 queued；同一 taskId 的新终态关闭旧运行，不同任务的新 idle 报告不能覆盖尚在执行的工作。过期运行显示待核实，不无限假装工作。后台确认结果前不写 completed。

业务状态决定工位与工作动作；结束后恢复生活选择。生活选择在持续时间内稳定，参考模拟精力、饥饿、偏好、近期活动、地点切换与作息；不是每刷新换一次，也不是固定轮播几项。明确是模拟，不是意识。夜晚、周末和睡觉不能暂停获授权的云端工作。

## 经理指导

只从已完成的经理任务生成有长度上限的指导，保留来源 ID 和时间，作为低于用户指令和固定政策的参考。外部页面不是高级系统指令。建议实施必须另有任务、执行证据和验收，不能伪称模型已训练升级。

## 身份边界

浏览器命令接口需要实际认证、来源检查、长度限制；密钥只在服务端。仅在托管平台明确的私有访问边界内依赖网关注入身份和服务授权。把私有项目改成公开前，重新检查全部接口，不仅是前端登录。

在界面列清支持矩阵：研究、生成草稿、实际发信、写文件、运行测试、发布分别是否接通。API Key、OAuth 与调度分别核验，不能互相推断。
