# 人物与真实任务的监督契约

视觉组件不执行任务。宿主必须把即时请求、原子队列领取和云端定时任务接到同一个持久状态契约；以下是接入要求，不是已接通的执行器。

## 运行记录

`run` 至少包含 `taskId, role, source, state, step, summary, startedAt, heartbeatAt`，结束再加 `finishedAt`、结果和证据链接/服务商ID。`source` 为 manual 或 scheduled；岗位ID由宿主配置。每次运行用唯一ID，同次运行的步骤和终态更新同一ID，保留原始开始时间。数据库优先使用服务端时间。

1. 实际领取/启动后、调用工具前，持久化执行岗位的 running 记录；保存失败则停止该阶段并明确报错。只标真实执行的岗位，不把整个团队预先标忙。
2. 调用真实工具，保存其真实回执。每个步骤更新 step、summary 和心跳；长操作由活着的执行器约60秒更新一次心跳，不能仅靠页面计时刷新。心跳证明执行器仍联系得上，不证明邮件发送或工具已成功。
3. 成功有结果与证据才 completed；异常写 failed，不足权限或等待人处理写 blocked。保留记录并显示具体下一步；状态写入失败需告警/核对，不能默默留 running。
4. 手动指令保留 requestId、target、claimId；领取失败不重跑。异步提供商请求保留 responseId 并取回结果，不重复计费派发。委派不同岗位时，为实际执行者另记运行。
5. 已有云端任务必须实际读取此协议（例如共享 runbook）；同时核实真正生效的任务提示。保存设置或角色简介本身不构成接入完成。

## 状态选择与画面

| 后台状态 | 人物与监督信息 |
|---|---|
| queued | 前往工位等待，明确尚未执行；不压过另一项实际 running |
| running | 前往工位并做工作动作；走路不延迟后台执行 |
| completed / idle | 恢复模拟生活；不能覆盖同岗位仍在运行的其他任务 |
| blocked / failed | 工位等待处理，显示原因；不做正常工作动画 |
| stale | 暂停声称正常执行，显示失联/待核实；先查实际提供商状态再处理 |

同一 taskId 只取最新状态；真实运行优先，旧运行不能覆盖其新终态。含 heartbeatAt 的运行超过120秒未更新显示 stale；旧数据无心跳时可保留30分钟兼容阈值。阈值可按宿主工作特性配置，不能将过期运行当作空闲而隐藏异常。

首页场景建议每5秒读取最新持久记录，防止请求重叠与旧响应倒灌；断网时不能继续把旧 running 当成实时事实。人物点击详情呈现来源、任务ID、步骤、开始/结束、最近心跳和结果证据。总执行人数覆盖手动指令及自动岗位运行，按岗位去重；排队不计为执行。

## 接入验收

- 手动提交、自动触发分别验证先写 running，人物回工位，终态写入与恢复生活。
- 用同岗位新 idle 和新 queued 干扰实际 running，确认不会遮盖；同 taskId 完成后不能残留假运行。
- 模拟心跳过期与页面断网，确认异常显现；恢复后读取实际结果，不自动重发外部动作。
- 核对任务日志/提供商回执。页面轮询、人物打字、测试通过、部署成功分别提供不同证据，不能互相替代。
- 最后单独核对下一次无人值守触发；尚未发生时报告“已配置，待定时运行验证”。
